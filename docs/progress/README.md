# 个人进度记录规则

## 谁写哪个文件

| 文件 | 谁写 | 谁读 |
| --- | --- | --- |
| `docs/status.md` | **只有 PO** | 所有人 + AI |
| `docs/progress/<你的GitHub用户名>.md` | **只有本人** | 所有人 + AI |

## 为什么这样分

4 个人改同一个文件，合并时必然冲突；而且每个人手上的都是几小时前的版本。
**一人一个文件 = 永远不会改到同一行 = 零冲突。**
总览只有一个人写，也零冲突。

## 什么时候更新（每次 10 秒）

1. **认领任务时**：把「当前任务」改成任务名，状态写「进行中」。
2. **开 PR 时**：状态改成「待评审」，附上 PR 链接。
3. **合并后**：状态改成「已完成」，写下一行「下一步」。
4. **卡住时**：状态写「卡住」，并写清楚卡在哪（谁要帮你、缺什么）。

## 模板

```markdown
# <姓名> 的进度

最后更新：YYYY-MM-DD
当前任务：[任务名]（批次 N）
状态：未开始 / 进行中 / 待评审 / 已完成 / 卡住
卡在哪：（没有就写"无"）
下一步：
```

## 给 AI 助手的指令（复制给你的 AI）

> 开工前先读 `docs/status.md` 和 `docs/progress/<我的用户名>.md`。
> 完成一个任务后，**只更新我自己的那个文件**，不要改别人的，也不要改 `docs/status.md`（那只有 PO 能改）。

## 注意

- **不要动别人的文件**，即使发现了错误，也只在群里说，由本人改。
- 文件名必须用 **GitHub 用户名的小写形式**，避免重复。
