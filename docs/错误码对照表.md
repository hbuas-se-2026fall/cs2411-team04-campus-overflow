## 编码规则

**前缀 = 上下文**：`QA-` Q&A、`ID-` Identity、`REP-` Reputation、`DIS-` Discovery、`AUTH-` 认证、`SYS-` 系统。

**首位数字 = 异常族，决定 HTTP 状态**：

| 首位 | 异常族 | HTTP | Java 异常类 |
| --- | --- | --- | --- |
| `1xxx` | 业务规则 | 422 | `BusinessRuleException` |
| `2xxx` | 冲突 | 409 | `ConflictException` |
| `3xxx` | 禁止 | 403 | `ForbiddenException` |
| `4xxx` | 未找到 | 404 | `NotFoundException` |

异常类在 `backend/co-shared-kernel/src/main/java/com/campusoverflow/shared/domain/`，HTTP 状态由其 `suggestedStatus()` 决定。

## 新增错误码的约定

1. **先 grep 再新增**：`git grep -n -E '"(QA|ID|DIS|REP)-[0-9]{4}"' -- 'backend/*.java'`，确认不重号。
2. **已出现的码以代码为准**：不要为了「好看」改历史码 —— 改了前端提示与测试都会跟着坏。
3. **首位数字必须与异常类匹配**：`1xxx`→`BusinessRuleException`(422)、`2xxx`→`ConflictException`(409)、
   `3xxx`→`ForbiddenException`(403)、`4xxx`→`NotFoundException`(404)。

   反例（本表已如实记录）：`QA-1018` 用了 `1xxx` 却抛 `NotFoundException`（404）。运行时行为没错（HTTP 由异常类决定），
   但编号违反约定；指导书对应的是 `QA-4003`，**是否修正由 PO 决定，本卡不改 Java 文件**。

## 如何重新生成这张表

```powershell
# 1) 列出所有码及位置（跨平台，Windows 也能用）
git grep -n -E '"(QA|ID|DIS|REP|AUTH|SYS)-[0-9]{4}"' -- 'backend/**/src/main/**/*.java'

# 2) 只列唯一码
git grep -h -o -E '"(QA|ID|DIS|REP|AUTH|SYS)-[0-9]{4}"' -- 'backend/**/src/main/**/*.java' |
  ForEach-Object { $_.Trim('"') } | Sort-Object -Unique
```

> **口径说明**：以上命令限定 `src/main`，实测 **26 个文件 / 86 处**，与本表统计一致。
> 若改用 `'backend/*.java'` 宽口径会返回 **131 行** —— 多出的 45 处来自 10 个测试文件。
> 「新增错误码前查重」那一节**故意保留宽口径**：测试里断言的码同样算「已被占用」，宽口径更容易暴露撞号风险。

> 注意：`Guard.requireText(...)` / `Guard.requireNonNull(...)` 的码出现在**参数列表**里，不是 `throw` 语句；
> 它们的「中文含义」由 `Guard` 拼接而成（`backend/co-shared-kernel/src/main/java/com/campusoverflow/shared/domain/Guard.java`）：
> 空值 → 「{字段名}不能为空」，长度越界 → 「{字段名}长度应在 {min}–{max} 个字符之间」。
> 统计口径：60 个唯一码 / 86 处（`develop@c6b0e46`，2026-11-18）。
