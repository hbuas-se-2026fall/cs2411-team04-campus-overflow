## 二、10 步演示

### 第 1 步：学生 A 登录（约 30 秒）

- **操作**：<http://localhost> → 右上「登录 / 注册」→ 学号 `2023001`、密码 `Campus2026` → 点「登录」
- **看到**：右上角显示「小明 STUDENT」，首页出现「我要提问」
- **说明**：登录态存在 Redis 服务端会话（Cookie 名 `SESSION`，HttpOnly）

### 第 2 步：学生 A 提问（约 1 分钟）

- **操作**：点「**我要提问**」→
  - 标题：`红黑树插入后什么时候需要左旋？`
  - 正文：`按《算法导论》的插入流程，叔叔节点为黑时需要旋转，但我不理解为什么不能只靠变色解决，能否用示例说明？`
  - 标签：`数据结构 红黑树`
  - 所属课程：`CS2001 数据结构`
  - 点「**发布问题**」
- **看到**：跳到 `/questions/<id>`，标题下方标「0 个回答」
- **数字**：小明的声誉**不变**（提问不加分）

### 第 3 步：学生 B 回答（约 1 分钟）

- **操作**：右上「退出」→ 登录 `2023002` → 打开刚才的问题 → 底部「**写回答**」输入：
  `关键在于黑高这个不变量：变色只能局部交换红黑属性，不能改变某条路径上黑节点的个数，所以必须靠旋转调整结构。`
  → 点「**提交回答**」
- **看到**：「1 个回答」，回答作者显示「小红」
- **数字**：小红的声誉不变，但获得徽章 **初来乍到**（首个回答）

### 第 4 步：学生 C 投票（约 1 分钟）

- **操作**：退出 → 登录 `2023003` → 打开该问题 → 在小红的回答左侧点 `▲`
- **看到**：分数 `0 → 1`
- **数字**：小红声誉 **`+10`**
- **补充（可选）**：再点一次 `▲` 撤销（`−10`）；或点 `▼` 改投（`−12`，按差值一次扣减）

### 第 5 步：学生 C 评论并 @A（约 30 秒）

- **操作**：在回答下方点「**添加评论**」→ 输入 `@小明 这个解释比我查的资料清楚` → 点「**发表**」
- **看到**：评论出现在回答下方
- **说明**：`@昵称` 目前只是文本标记，**不会推送通知**（通知功能属 Sprint 4）

### 第 6 步：教师认证（约 30 秒）

- **操作**：退出 → 登录 `T2001` → 打开该问题 → 在小红的回答下点「**教师认证**」
- **看到**：回答旁出现「教师认证 · 王老师」
- **数字**：小红声誉**不变**；获得徽章 **名师认可**
- **答辩点**：认证是背书，不是加分；加分只来自投票与采纳

### 第 7 步：教师发起悬赏（约 1 分钟）

- **操作**：仍是 `T2001`，在问题页点「**发起悬赏**」→ 弹出「悬赏积分（10–500）」，填 `50` → 点「确定」
- **看到**：问题页出现「悬赏 50 分」
- **数字**（教师账户）：可用积分 `1000 → 950`，冻结积分 `0 → 50`，**声誉不变**
- **答辩点**：冻结 ≠ 扣款；到期未采纳要原路退回，所以必须先冻结
- **追问预案**：「学生能不能发悬赏？」→ 不能。学生开户 0 分，且领域规则只允许课程管理者发起（`REP-3001`）
- **注意**：「发起悬赏」与「删除问题」两个链接相邻，别点错

### 第 8 步：学生 A 采纳（约 1 分钟）

- **操作**：退出 → 登录 `2023001` → 打开该问题 → 在小红的回答下点「**采纳此回答**」
- **看到**：回答左上角出现 `✔`，问题变为已采纳，悬赏结束
- **数字**（同时发生三件事）：
  1. 小红声誉 **`+15`**（采纳；自己采纳自己不加分）
  2. 小红声誉再 **`+50`**（悬赏以**声誉**结算，不进入钱包）
  3. 教师冻结积分 `50 → 0`（这 50 分不会转进小红账户）
- **徽章**：小红获得 **初露锋芒**（首个回答被采纳）

### 第 9 步：看个人声誉页（约 30 秒）

- **操作**：退出 → 登录 `2023002` → 导航「排行榜」→ 点「小红」→ `/users/5`
- **看到**：
  - 声誉值 **110**（基线 35 + 本次 10 + 15 + 50）
  - 可用悬赏积分 / 冻结中：`0 / 0`
  - 徽章 4 个：初来乍到、名师认可、初露锋芒、小有名气（声誉到 100 时自动授予）
  - 声誉流水 6 条：种子 3 条（问题 #1）+ 本次 3 条（问题 #4）
- **答辩点**：流水只追加；账户声誉恒等于流水之和（每日 03:30 自动对账）

### 第 10 步：排行榜（约 30 秒）

- **操作**：点导航「排行榜」→ 依次切「本周 / 本月 / 本学期 / 总榜」
- **看到**：总榜 6 人，小红以 **110** 排第 1，小明 10 第 2，其余 0
- **答辩点**：排行榜读 Redis 缓存，最终一致（约 1–2 秒刷新）；周期边界按北京时间
- **注意**：本次演示数据都产生在当天，四个周期结果相同，属正常

## 四、常见问题（演示现场排障）

**① 容器起不来，报 `bind: ... access permissions`**

本机 Windows 的 6379 可能落在系统保留端口段（6366–6465）。管理员 PowerShell：

```powershell
net stop winnat
docker compose -f deploy/docker-compose.yml up -d
net start winnat
```

**② 端口被占用**

```powershell
netstat -ano | findstr :80
netstat -ano | findstr :8080
```

结束占用进程后重试。

**③ 演示数据没重建（登录失败 / 问题列表是旧的）**

`demo` profile 只在**库为空**时播种：`DemoDataSeeder` 发现「系统管理员」已存在会跳过。
处理：`docker compose down -v` 后重新 `up -d`。

**④ 声誉一直不变**

```sql
-- 进入 MySQL 容器
docker exec -it co-mysql mysql -ucampus -pcampus_dev_pwd campus_overflow
-- 查看未投递事件
SELECT id, event_type, published_at, attempts, last_error FROM outbox_event WHERE published_at IS NULL;
```

- 有 `last_error` 说明某个监听器抛异常，会阻塞本批后续事件
- 修复后重放：`UPDATE outbox_event SET attempts = 0, locked_until = NULL WHERE published_at IS NULL;`
- 再查 `rep_ledger` 是否有对应流水

**⑤ 搜索框 / 通知页 / 「相关问题」报错或为空**

属 Sprint 4 的 Discovery 范围（`#66`/`#67` 未完成），演示时**不要点**这几处。

**⑥ 页面是旧的**

`Ctrl + F5` 强刷；确认访问的是 `http://localhost`（80 端口）。
